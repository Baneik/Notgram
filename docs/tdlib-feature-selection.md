# Notgram TDLib 功能取舍清单

> 文档基线：2026-08-06<br>
> 代码基线：`main@d8a3e2e`<br>
> TDLib 基线：`022d60202e446ad1287b9fb68e687c8a0760788b`<br>
> 用途：由产品负责人勾选 Notgram 是否接入某项能力，以及接入到什么深度。未勾选不代表 TDLib 不支持，只表示当前没有产品承诺。

## 1. 使用方法

每项功能先选择一个决策：

- [ ] 接入
- [ ] 不接入
- [ ] 延后评估

如果选择“接入”，再选择一个主要深度：

- [ ] **C：兼容显示**——只保证收到相关消息或服务事件时不崩溃，提供安全摘要和原始信息降级，不提供主动入口。
- [ ] **R：只读体验**——可以浏览、搜索或查看详情，但不能创建、发送或管理。
- [ ] **I：核心交互**——覆盖最常见的创建、发送或管理动作，不追求 Telegram 官方客户端的全部选项。
- [ ] **F：完整体验**——覆盖创建、编辑、删除、权限、失败恢复、实时更新、Mock、原生验收和高级设置。

补充选择可以直接写在每项的“产品备注”中。若一个大功能只需要部分子能力，应勾选核心交互，并明确保留和排除的子能力。

## 2. 无论是否接入都必须保留的兼容底线

以下项目不是可选产品功能，而是消息安全和兼容性底线：

- 已知但未接入的消息类型必须显示安全摘要，不能导致会话、历史同步或通知崩溃。
- 未知未来消息保留“暂不支持”降级和开发者原始消息复制，不猜测可执行行为。
- 未接入功能不显示无响应的按钮，不注册多余后台同步，不扩大 Rust TDLib allowlist。
- 只有在用户选择接入后，才增加 Transport 方法、Store 状态、UI 入口和持久化字段。
- 新功能必须支持 TDLib 错误、取消、迟到更新、账号切换和断网恢复，不能只实现成功路径。
- Mock 用于确定性行为回归；通话、通知、文件、WebView2、安装器等原生边界必须单独验收。
- 所有本地文件路径、媒体设备权限和特权 TDLib 命令继续留在 Rust 可信边界内。

## 3. 通用接入流程

选择 I 或 F 时，默认按以下顺序实现：

1. 明确用户入口、默认值、失败状态和不支持范围。
2. 仅开放所需 TDLib 请求，并在 Rust 校验字段、文件和权限边界。
3. 扩展 `TelegramTransport`、TDLib 映射和实时更新路由。
4. 把持久业务状态放入独立 Store/模块，避免继续堆积到单一编排文件。
5. 增加 UI、键盘、窄屏、强制色和无障碍行为。
6. 增加 Vitest/Rust/Mock E2E；涉及真实边界时增加原生冒烟项目。
7. 更新 changelog、诊断指标和发布验收清单。

- 贴纸、GIF、图片和普通文件发送；媒体下载、保存、打开、自动下载和缓存清理。
- 图片、视频、视频消息、音频、语音、动画、贴纸和文档的接收与基础播放/查看。

## 4. 日常消息能力

### F01 原生视频、音频和文件类型发送

**描述**：按 Telegram 原生类型发送视频、音频、动画和文档，使接收端获得正确播放器、时长、缩略图、流式播放和搜索分类。

**当前状态**：JPG/PNG 作为图片发送；其他格式包括视频和音频均按普通文档发送。

**决策**：

- [ ] 接入
- [ ] 不接入
- [ ] 延后评估

**接入深度**：

- [ ] C：保持当前文档发送和接收侧正确显示。
- [ ] I：按 MIME/扩展名构造 `inputMessageVideo`、`inputMessageAudio`、`inputMessageAnimation`，生成基础缩略图和元数据。
- [ ] F：增加压缩/原文件选择、封面、静音、剧透、caption 位置、上传取消恢复和混合媒体规则。

**主要 TDLib 范围**：`sendMessage`、`sendMessageAlbum`、`inputMessageVideo`、`inputMessageAudio`、`inputMessageAnimation`、`editMessageMedia`。

**体验与成本**：高日用价值；需要本地元数据探测、相册兼容、安全文件命令和大文件原生测试。

## 12. 推荐的决策原则

- 优先选择能减少日常操作摩擦、且不会长期占据主界面的能力。
- 展示兼容与主动创建分开决策；例如可以选择“参与投票”，但不提供复杂投票创建器。
- 管理类能力可以只对具备权限的用户按需加载，不必加入常驻导航。
- 高风险能力如通话、Web App、支付和秘密聊天，只有在可以完成原生验收与安全闭环时才进入 I/F。
- 如果某项能力只在官方 Telegram 客户端中偶尔使用，可以保留 C/R，并提供“使用官方客户端完成”的明确提示。
- 每个版本只选择少量能力，优先完成纵向闭环和回归测试，再选择下一批。

# 频道帖子讨论区功能覆盖审计

> Historical audit: findings apply to the dated baseline and may have been superseded. See the [current project overview](../../README.md#architecture) for the maintained structure.

日期：2026-08-30

## 结论摘要

频道帖子的评论不是频道消息的特殊子类型，而是关联讨论组中的普通消息。客户端必须使用
`(chatId, messageId)` 作为消息身份：帖子使用频道 `chatId`，根讨论消息与评论使用关联讨论组
`chatId`。此前媒体大图、reaction 列表以及部分消息操作错误地沿用了当前频道 `chatId`，属于
客户端路由 bug，不是 TDLib 能力限制。

本轮已经修复媒体与 reaction 的跨聊天路由，并补齐回复/引用回复、消息菜单、发送者资料入口、
`@` 提及、`#` 标签和输入焦点。评论消息现在复用普通会话的消息渲染与操作能力，并将所有写操作
显式路由到关联讨论组。

审计仍发现四类重要产品缺口：长讨论历史分页、离线 outbox、讨论已读同步、阻止用户内容遮罩。
这些能力 TDLib 均可支持或客户端已有可复用机制，不能归为 TDLib 限制。

## 审计范围与方法

- 对比普通会话 `Conversation` 与帖子讨论区 `ChannelDiscussionPanel` 的展示、操作、发送和导航链路。
- 检查 store、transport、TDLib 请求参数及消息缓存键，重点验证关联讨论组 `chatId`。
- 检查文字实体、媒体、文件、投票、reaction、inline keyboard、发送状态和服务消息的共享渲染路径。
- 增加 store 回归测试，并以无头 Playwright 覆盖真实 UI 操作和焦点恢复。
- 结论按“已覆盖”“客户端 bug”“客户端未覆盖”“TDLib 限制”分类。

## 已修复的客户端 bug

| 问题 | 根因 | 修复结果 |
| --- | --- | --- |
| 评论图片不能打开大图 | 媒体查看器只收集当前频道消息，且打开媒体时缺少评论的实际 `chatId` | 评论图片加入查看器媒体源，并使用关联讨论组 `chatId` 打开 |
| reaction 列表报错 | reaction 明细请求使用当前频道 `chatId` 请求讨论组消息 | reaction 明细始终使用消息自身 `chatId`；同 ID 跨聊天也不会串路由 |
| 评论消息操作偶发作用到错误消息 | 多个操作只按 `messageId` 查找，而消息 ID 只在单个聊天内唯一 | 编辑、删除、转发、置顶、上传取消等操作均支持显式 `chatId` |
| 评论区贴纸/GIF 发到频道上下文 | picker 接收了讨论组 `chatId`，store 调用却仍读取 active chat | sticker/animation 发送显式传入讨论组 `chatId` |
| 评论回复忽略引用内容 | 讨论发送链路只传回复目标，没有传 quote | 文字和附件均透传引用文本、位置和实体 |
| 媒体窗口返回后输入框失焦 | 讨论面板没有普通会话的焦点恢复机制 | 打开面板、执行操作、关闭弹层和窗口重新获得焦点时恢复 composer 焦点 |

## 消息内容类型覆盖

讨论区和普通会话现在共用 `MessageBubble` 内容渲染路径，因此以下类型没有独立的“评论版”实现：

- 文本、富文本实体、spoiler、caption、服务消息和不支持类型提示。
- 图片、视频、圆形视频、动画、贴纸、语音、音频和通用文件。
- 投票、reaction、inline keyboard、上传/下载进度、失败重试。
- 回复预览、转发来源、频道署名、管理员标签和消息发送状态。

图片大图已通过讨论组 `chatId` 的 E2E 用例验证。视频使用与普通会话相同的渲染和画中画链路，
不存在讨论区专用分支；本轮验证了共享路径与菜单接线，但没有将真实编解码播放作为自动化断言。

## TDLib 的真实能力限制

| 能力 | 边界 | 客户端处理 |
| --- | --- | --- |
| reaction 发送者明细 | `can_get_added_reactions=false` 时不可枚举；付费 reaction 不能按普通 reaction 获取身份列表 | UI 禁止发起不可用请求，并保留汇总计数 |
| 帖子级跨设备草稿 | TDLib 草稿以 chat/forum topic 为作用域，没有“频道帖子所映射的任意消息线程草稿”同步模型 | 使用本地按帖子缓存；不宣称跨设备同步 |
| 消息权限 | 编辑、删除、置顶、获取 reaction 明细等取决于 TDLib 返回的消息/聊天权限 | 菜单按 capability 隐藏或禁用，不绕过服务端权限 |

评论本身、评论媒体大图、评论 reaction、引用回复、实体点击和消息菜单都不是 TDLib 限制。

## 仍未覆盖的客户端能力

| 优先级 | 缺口 | 影响 | 判定 |
| --- | --- | --- | --- |
| P1 | 长讨论历史分页 | transport 单次最多取 100 条，面板尚无向上分页；超过 100 条时旧评论不可达 | 客户端未覆盖，TDLib 支持 `from_message_id`/offset 分页 |
| P1 | 离线 outbox | 普通会话可进入离线队列，讨论文字、附件、贴纸和 GIF 当前离线直接失败 | 客户端未覆盖，可复用普通会话队列 |
| P1 | 已读/未读同步 | 面板展示讨论组消息时未显式上报可见消息或清除对应 attention | 客户端未覆盖，TDLib 支持 view/read 相关请求 |
| P1 | 阻止用户内容遮罩 | 普通会话的本地 blocked-user 展示策略没有完整接入讨论面板 | 客户端未覆盖，可复用现有策略 |
| P2 | 大量评论虚拟化 | 普通会话使用虚拟列表，讨论面板当前直接渲染 | 客户端体验缺口 |
| P2 | 音频连续队列 | 单条音频可播放，但讨论区未建立普通会话的上一首/下一首队列 | 客户端体验缺口 |
| P2 | 置顶消息浏览入口 | 可以置顶/取消置顶，但面板内没有置顶消息 banner/history 入口 | 客户端体验缺口 |
| P2 | 相册视觉聚合 | 可以按 media album 合并转发，但讨论显示尚未聚合为相册布局 | 客户端体验缺口 |
| P3 | 拖拽范围多选 | 点击多选与工具栏已覆盖，普通会话的拖拽范围选择未接入 | 客户端体验缺口 |

## 验证覆盖

新增或扩展的自动化验证包括：

- 同一个 `messageId` 同时存在于频道和讨论组时，reaction、编辑、删除、置顶、贴纸和草稿仍路由到讨论组。
- 评论 reaction 列表可以加载，不再产生 unexpected-chat 类错误。
- 评论图片点击后打开大图媒体窗口。
- 回复、引用回复、编辑、转发、复制、选择、删除和发送者菜单可用。
- 发送者头像、`@` 提及、`#` 标签的目标和搜索范围正确。
- 执行回复、编辑、菜单操作及发送后，评论 composer 保持或恢复输入焦点。

最终验证结果：`npm run check` 通过（88 个测试文件、636 个前端测试、生产构建、E2E 类型检查、
89 个 Rust 测试），四个频道讨论 Playwright 场景全部通过。本报告对应工作区未提交状态。

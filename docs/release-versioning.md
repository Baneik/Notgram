# Release versioning

`version.json` is the only manually edited application version. After changing
it, synchronize the generated manifest values:

```powershell
npm run version:sync
```

This updates `package.json`, `package-lock.json`, the Cargo package and lockfile,
and the Tauri bundle. `npm run check` rejects version drift through
`npm run version:check`.

Release tags are annotated tags named exactly `v<version>`. Create a tag only
from a clean commit after the local release checks pass and a matching heading
is present in `CHANGELOG.md`:

```powershell
$version = (Get-Content version.json -Raw | ConvertFrom-Json).version
git tag -a "v$version" -m "Notgram $version"
git push origin "v$version"
```

Stable releases use `MAJOR.MINOR.PATCH`; candidates use a SemVer prerelease such
as `0.5.0-rc.1`. Never move or replace a published tag. Publish a new patch or
prerelease when a release must be superseded.

Signed releases are produced locally. Keep the signing certificate in the
current user's certificate store and provide its SHA-1 thumbprint through
`NOTGRAM_CERTIFICATE_THUMBPRINT`. The release process also reads
`NOTGRAM_API_ID`, `NOTGRAM_API_HASH`, `NOTGRAM_UPDATER_PUBLIC_KEY`, the HTTPS
`NOTGRAM_UPDATE_BASE_URL`, and Tauri's updater signing key environment
variables. Keep all credentials in the process environment; do not write them
to tracked files or release artifacts.

Run `scripts/release-preflight.ps1 -RequireSigning`, `npm run check:release`, and
`npm run test:e2e` from a clean release commit. Prepare the pinned TDLib runtime,
then use the scripts in `scripts/` to sign and verify native files, build and
stage the installer and portable archive, produce the update channel, and run
the lifecycle checks. Publishing the staged files to a release host is an
explicit manual step; this repository does not contain hosted automation
configuration.

Store the exact one-line contents generated by `tauri signer generate` for the
updater private `.key` and public `.key.pub` files. Those values are already
Base64-encoded Tauri key records and must not be encoded a second time. The
public value is embedded in the application so downloaded updater installers can
be verified before installation; the private value is exposed only to the
release build process.

Stable versions read `stable/latest.json`; prereleases read
`candidate/latest.json`. `release-policy.json` is the machine-readable source
for the minimum compatible version, cache schema, channel rules, and retained
rollback window. Automatic and installer downgrades are disabled. Rollback is a
forward-only release: rebuild the previous verified source as a higher patch or
prerelease, pass the complete local release procedure, then advance the channel
manifest. Keep the latest two signed release sets available until the new build
passes startup and data-restoration checks.

`artifacts/update` is a deployment payload, not the channel host itself. Publish
its complete `stable/` or `candidate/` directory to the matching path under
`NOTGRAM_UPDATE_BASE_URL` only after the immutable release assets are available
on the chosen release host. Preserve the staged payload separately for audit or
restoration; a failed deployment leaves the previous signed `latest.json` and
updater installer active. Stable releases advance both channel manifests so
existing candidate installs can move forward to the stable build; prereleases
advance only the candidate manifest.
